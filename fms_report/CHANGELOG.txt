FMS TEST RESULTS REPORT - VERSION LOG
Motion Rail  ·  Alkis Kardasopoulos
=====================================================================

v1.6  (2026-10-09)   Pick the cable, cleaner Cable View, date-first filenames
  - Pick the cable, not the two RTUs. The wizard now lists the cables and, when you
    choose one, finds the RTU facing each end (End A / End B shown before the pull).
    New --cable flag does the same from the command line, e.g. --cable RGAC-SNBC.
    --rtu-a / --rtu-b still work and override it.
  - End A / End B are always oriented east to west (End A is the more easterly site),
    so the orientation never flips with the cable name order or which end you type.
  - The Cover now shows "Generated by (FMS user)": the FMS login used for the pull.
  - Cable View starts at A1: the in-sheet "Cable View" title is gone (the tab is already
    named), so the data sits at the very top with no wasted rows.
  - Report filenames now lead with the test date then the cable ID:
    <dd-mm-yy>_<cable>_<ribbons>_<time>.xlsx, e.g. 08-10-26_RGAC-SNBC_Rall_2347.xlsx.
  - The report prompt reads [Y/N] (was [Y/n]).

v1.5  (2026-10-08)   Motion logo, tidier Cable View, remedial tracking
  - Cover now shows the Motion Rail logo (drop logo.png beside the tool) and carries the
    analysis settings moved off Cable View (Good / Medium splice, Hydra length, wavelengths).
  - Cable View: the settings block at the top is removed, so results start near the top
    and more fibres are visible on screen.
  - Remedial tracking across runs. The "Splices > 0.15dB" sheet gains Status / Prev @1550 /
    Change columns tagging each remedial NEW, EXISTING, IMPROVED or WORSE, and a new
    "Remedial Tracking" sheet summarises movement and lists cleared splices. History is
    kept in remedial_history.json beside the tool, keyed by cable.

v1.4  (2026-10-06)   Run log, and clear reporting of missing results
  - Every run now writes a plain-language log next to the workbook,
    <workbook>_runlog.txt. It lists each fibre as EXPORTED, SKIPPED (with the
    reason, e.g. only an OTDR test, or tested outside the date range) or
    NOT EXPORTED (e.g. no test on this cable, or a token/connection error
    mid-run), then a WORKED / SKIPPED / ISSUES summary and data-quality notes.
  - The console prints where the log saved and its name, and says plainly
    whether any fibre failed, so genuinely missing results can be told apart
    from explained skips at a glance.
  - Under the hood, fetch_iolm now reports why it found nothing (no result,
    wrong test type, no loss data, outside the date window, or no asset id)
    so the log can give a reason per fibre. No change to report content.

v1.3  (2026-09-28)   Cable View layout closer to the EXFO report
  - Cable_View gets a summary block above every joint: splice count, min and
    max one-way reading, and the average bidir loss, filled red or amber when
    it is over the Good / Medium splice limits.
  - Each fibre is now a clear two-row block: fibre ID merged over both rows
    in bold, one-way readings in blue, the average in bold black underneath,
    and a heavy line under each fibre.
  - Solid red (#DC3545) and amber (#FFC107) fills with black text on both
    cable views, as in the EXFO report. Good values are no longer green.
  - The ODF columns now show the ODF connection reading from the ODF
    Connection sheet (A end A-B only, B end B-A only). They previously
    picked up the launch group near 0 m, which included the RTU switch.

v1.2  (2026-09-28)   Splice nominal asked in the wizard, default 0.02
  - The wizard now asks for the splice nominal after the ribbons. Press Enter
    for 0.02, or type another value (0 to 1 dB). It is used wherever one
    direction found no splice, and shows on the Cover.
  - Default changed from 0.06 to 0.02 to match the EXFO customer report.
    --splice-nominal on the command line still overrides it.

v1.1  (2026-09-28)   Remedials grouped by location
  - The Remedials tab is no longer one flat worst-first list. Rows are grouped
    by Location in route order (A end first, by the lowest scheduled distance
    in each group, measured distance if no schedule). Within a location, rows
    run by ribbon, then worst loss first. Unlocated rows go last, under
    "(No location)".
  - Every location gets a summary row underneath it: splice count, ribbon
    count and worst loss, written as live formulas so they stay right if rows
    are edited.
  - Each location is a collapsible outline group; use the 1/2 buttons to see
    just the summary lines. Saved expanded. Filter, frozen header and loss
    colours are unchanged.

v1.0  (2026-09-28)   First project release
  - Version numbering starts here. The banner now shows v1.0 and the build
    date, and reports can be traced to the exact build that made them.
  - Cable_View and Detailed Cable View gain a LOCATION row above the distance
    row. Each joint column is named after the scheduled physical location, so
    a column reads "Pangbourne Station REB" rather than only "8961".
    Joints with no scheduled match are marked (unscheduled).
  - Both cable views group their fibres into collapsible ribbon blocks, with
    the +/- control on the ribbon header row, the same way the EXFO report
    does it. Ribbon numbers come from the fibre number, not from row order,
    so a part-ribbon pull is still labelled correctly.
  - Location naming is now ONE-TO-ONE: each event and each joint column takes
    the closest scheduled location, closest pair first, and a location can
    only be claimed once. This fixes spurs reading "A-01 Spur West" three
    times where East / REB / West sit ~35 m apart. Anything left over shows
    as an unscheduled joint rather than duplicating a name.
  - Distances.xlsx rev 1.2 carries the measured NRS-304 distances for
    F-RGAC-SNBC, both directions, 53 locations.

v0.31  (2026-08-30)   Distances are versioned and traceable
  - Distance sheets carry REV: and ISSUED: alongside CABLE / FROM / TO, so the
    file is self-describing and can be issued on its own without the tool.
  - Every report names the exact revision it used, on its Cover:
      Distance schedule: Distances.xlsx / Reading to Swindon /
                         F-RGAC-SNBC rev 1.3, issued 2026-08-30
    A workbook can therefore be traced back to the distances behind it later.
  - Distances.xlsx gains a Revisions sheet: rev, date, sheet, what changed, by.
  - --list-cables shows the revision and issue date per sheet, and the run warns
    on any sheet with no REV tag.

v0.30  (2026-08-30)   Ready to hand out
  - Folder cut to 6 files. One launcher, "FMS Report.bat", which installs its
    own dependencies on first run. Setup bat, requirements.txt, the schedule
    template and the verify CSV template are all gone.
  - First run asks for your FMS username and saves it to settings.json, so the
    folder can be zipped and passed to someone else and it asks them for
    theirs. The password is still never stored.
  - Distance sheets are now tagged with CABLE / FROM / TO in their top rows and
    matched against the cable being pulled, instead of being inferred by trying
    each sheet against the data. Inference stays as the fallback.
  - --list-cables shows what Distances.xlsx covers.
  - If Distances.xlsx is missing it is created with the tagging rows in place.

v0.29  (2026-08-20)   Split only what is location-dependent
  - --split now produces ONE cable-wide workbook plus one per ribbon group.
      <ends>_Rall-CABLE_<ts>.xlsx   all fibres: E2E loss, ODF connection,
                                    summary and the client verify
      <ends>_R3-18_<ts>.xlsx        that group only: splices by location
  - End-to-end and connector loss are the same regardless of route, so they
    belong in one place. Only the splice-by-location material is split.

v0.28  (2026-08-20)   One pull, several reports
  - --split "1-2,3-18,19-20,21-36" builds a separate workbook per ribbon group
    from a SINGLE pull. The server is queried once; each workbook contains only
    fibres that share a route.
  - Needed because ribbon groups take different paths, so their joints sit at
    different distances. Merged into one sheet, a column would line up
    locations that are not the same place.
  - Each workbook is named for its group, e.g. 0057-RGAC_R3-18_<date>_<time>.xlsx

v0.27  (2026-08-20)   Verify against a CLIENT report
  - --verify now recognises a client "Customer Cable Report" workbook and reads
    it directly. No re-keying, which matters because transcription is exactly
    the error you are trying to measure.
  - Reads the E2E Loss Report sheet, both mirrored direction blocks, and the
    Splices sheet. Writes a "Client Verify" tab: their value, my value, the
    difference, and a status per row.
  - The splice block shows the position gap as well as the loss difference. A
    difference only means something when the two reports are describing the
    same joint.
  - E2E: MATCH within 0.05 dB, CLOSE within 0.25. Splices: 0.02 and 0.08.

v0.26  (2026-08-20)   The RTU menu names the cable
  - Each site has an RTU per cable, so the RTU name alone never said which cable
    you were about to pull. The menu now derives it from the route names:
      [4] RTU2-SNBC-1991132  site=SNBC   432 routes   cable F-RGAC-SNBC
      [5] RTU2-SNBC2-1984400 site=SNBC2  432 routes   cable F-SGIC-SNBC
  - Same on --list-rtus. Nothing to configure, it comes from the data.

v0.25  (2026-08-20)   --find-route tells you what to run next
  - When two RTUs hold the same cable they are its two ends, so it now prints
    the ready-made bi-directional command instead of a vague hint.

v0.24  (2026-08-20)   Which CABLE, not just which RTU
  - An RTU is one end of several cables, and the route name says which. Picking
    the right RTU but the wrong cable gives a full, healthy looking report built
    on the wrong fibres, with nothing to hint at it.
  - The data check now names the cable: "cable: F-RGAC-SNBC-* (432)".
  - New --find-route TEXT says which RTU holds routes whose names contain TEXT,
    e.g. --find-route SGIC-SNBC.

v0.23  (2026-08-20)   Data check before the report is built
  - The run now stops and shows what it is about to use: test dates with a
    histogram of how many fibres each covers, newest and oldest, test types,
    traces with no result, and fibres with a newer eventless test. Then asks.
  - Flags a mixed-vintage pull spanning more than three days.
  - Points at --list-tests and --any-category when a recent test is missing.
  - -y skips the prompt, --no-check hides it entirely. Non-interactive runs
    continue automatically.

v0.22  (2026-08-20)   Seeing results the standard filter hides
  - The result filter is the one the FMS UI uses, and it deliberately excludes
    some categories: RLNulling, ScanMonitoring, most FastMonitoring, and any
    OTDR that is not Adhoc. A test run under one of those categories is
    invisible to the pull no matter how recent it is.
  - --list-tests now retries with a relaxed filter and says which one produced
    the results, so a hidden test can be seen.
  - --any-category runs the whole pull on the relaxed filter.

v0.21  (2026-08-17)   A mistyped password no longer ends the run
  - A 401 invalid_grant now re-asks for the password, up to three attempts,
    rather than exiting. Capped deliberately: Keycloak locks accounts after
    repeated failures, and each retry counts against that.
  - Clearer message. invalid_grant means the username or password was rejected,
    which is a different problem from the client id being wrong, and the old
    text pointed at the wrong one.
  - Only re-asks when the password came from the prompt. If FMS_PASS is set in
    the environment it says so, since a stale value there is a common cause.

v0.20  (2026-08-17)   Typing 'all' no longer crashes
  - The prompt said "blank = all", so typing the word all was reasonable. It
    went straight into int() and threw, after a 3,456 route enumeration.
  - 'all', '*', 'any' and blank now all mean every ribbon.
  - The spec is validated at the prompt and re-asked on a typo, so a bad entry
    costs you nothing instead of a full enumeration.
  - A single unreadable entry in a list is skipped with a note rather than
    killing the run.

v0.19  (2026-08-17)   Unlisted joints have to earn a column
  - An unlisted joint now needs to appear on at least 3 fibres before it gets a
    column. A real joint shows up on most fibres at the same distance; a cluster
    seen on one or two is a local feature or a detection artefact, and giving it
    a column filled the sheet with nominals dressed up as results.
  - --unmapped-min 1 keeps every one-off, --only-scheduled keeps none at all.
  - The run reports how many thin clusters were left out and how many events
    that covered, so nothing disappears quietly.

v0.18  (2026-08-17)   Return-leg joints were being dropped  [IMPORTANT]
  - Columns were only created from locations seen on the outbound leg. A
    scheduled location appears on both legs under one name so it was fine, but
    an unscheduled joint found on the return leg has a name of its own and was
    measured, stored, then never shown. On a 216 fibre pull that lost 10 of 44
    unscheduled columns.
  - Every location now gets a column whichever leg it appeared on.
  - label_unmapped now reports how many clusters hold only one fibre, so a
    scatter of one-off columns is visible rather than looking like real joints.

v0.17  (2026-08-17)   Honest warnings
  - The calibration warning compared the trace slope against a fixed 0.15-0.32
    band, so a legitimate short-range test tripped it. It now compares against
    the instrument's own AveragedLoss for that same measurement.
  - New SHORT-RANGE warning: if the traces do not reach as far as the schedule's
    furthest joint, the run says so loudly. Anything past the end of the
    acquisition is not in the data and can only fall back to the nominal.

v0.16  (2026-08-17)   Unscheduled joints measured too
  - An unscheduled joint column used to hold one real reading and a wall of
    nominals, because the curve measurement only visited scheduled distances.
    Those cluster distances are now measured on every fibre as well, so the
    column is real data like any other.

v0.15  (2026-08-17)   Binder and ribbon as columns
  - Backsplice Remedials and OTDR Measured now carry Binder, Ribbon and Fibre
    as three separate columns, so you can filter and sort on them.
  - A medium rule runs across the sheet wherever the ribbon changes, so ribbons
    read as blocks instead of one long list.

v0.14  (2026-08-17)   Curve fill was doing nothing  [IMPORTANT]
  - Since the switch to per-physical-fibre reporting, the curve fill matched on
    the route name while the rows were keyed by physical fibre, so it filled
    nothing and every gap quietly fell back to the nominal. It reported traces
    decoded but never said how many it filled, which is how it hid.
  - Now maps trace readings onto physical fibres the same way the event table
    does: main trace outbound to the main fibre A-B, main trace return to the
    loop fibre B-A, and the mirror of that for the loop trace.
  - It now always prints filled and still-nominal counts, so a silent zero
    cannot happen again.

v0.13  (2026-08-17)   Colour only where it means something
  - Only the average is highlighted, red at or over the pass threshold. A-B and
    B-A are left plain: a gainer in one direction is normal on a splice and
    colouring it reads as a fault when it is not.

v0.12  (2026-08-17)   Loop pairing when you filter one ribbon  [IMPORTANT]
  - Asking for a single ribbon of a loop returned only one leg. Ribbon 8 is
    carried under ribbon 7's route names, so the filter found 12 loop-back
    traces and none of their mains. With no pairs to find, the tool fell back
    to folding a single trace onto itself, which is the wrong pairing.
  - The filter now pulls in the partner leg of every route it matches, so a
    loop always arrives complete. Ribbons 7, 8 and 7-8 all give 24 traces and
    12 pairs.
  - The trace format line now reports the slope that was actually validated
    rather than an intermediate figure.
  - Gap count and fill count now use the same unit.

v0.11  (2026-08-15)   Nothing dropped, nothing blank
  - Backsplice remedials now include joints the distance schedule does not
    list. They are clustered by distance across fibres so the same unlisted
    joint lines up in one column, headed in amber and labelled (unscheduled).
    --only-scheduled goes back to the old behaviour.
  - A-B and B-A are never left blank under a populated average. Where the
    nominal is standing in, the cell now shows it as a live reference to the
    Cover, greyed and italic, so the average always has two visible numbers
    behind it and still recalculates when you change the nominal.

v0.10  (2026-08-15)   Ribbons, binders and looped naming
  - Ribbon filter now understands looped naming. Physical ribbon 4 lives under
    ribbon 3's route names on a loop, so asking for 4 used to return nothing.
    It now matches the description too and says which ribbons it reached.
  - Random ribbon lists work as expected:  3,6,8,11,25,36
  - Every results report now shows Binder and Ribbon in front of the fibre.
    Binder size is 6 ribbons by default, change with --per-binder.

v0.9  (2026-08-15)   Interface rebuild
  - Three report types instead of six mix-and-match options. End-to-end loss
    and connector loss now come with every report.
  - Remedials are included automatically with bi-directional and backsplice.
  - Backsplice sheet regrouped BY LOCATION: A-B, B-A and their average sit
    together under one merged header carrying the distances.
  - Branded console banner and this version log.

v0.8  (2026-08-15)   Fewer questions
  - Wizard cut from thirteen prompts to three: report, RTU, ribbons.
  - Distances.xlsx ships with the tool and is read automatically. Your copy is
    never overwritten by a new build.
  - RTU list cached for a day. Most of the old startup wait is gone.
  - Missing directions are measured off the raw trace automatically.
  - logo.png in the tool folder appears on the Cover.

v0.7  (2026-08-15)   Correct bi-directional pairing  [IMPORTANT]
  - A backsplice loop uses TWO physical fibres, out on one and back on the
    other. The tool was folding a single trace onto itself, which averaged one
    fibre's outbound reading with a different fibre's return reading.
  - Now reports one row per PHYSICAL fibre, pairing across the two traces.
  - Validated against hand-pulled figures: 42 of 48 fibres matched exactly at
    A-04; the rest were a transcription slip in the manual sheet or joints
    that had since been re-spliced.

v0.6  (2026-08-15)   Distance schedule sheets
  - Picks the sheet that fits the data instead of merging every sheet.
  - Reads ribbon spans ("R3-36") as well as explicit fibre ranges.

v0.5  (2026-08-14)   Resilience
  - Connection drops and 502/503 retried with a backoff.
  - Clean message instead of a Python traceback when the server is unreachable.

v0.4  (2026-08-14)   Cleaner reports
  - Launch and end-of-fibre events dropped from remedial lists.

v0.3  (2026-08-14)   OTDR events  [IMPORTANT]
  - OTDR results DO carry an event table, at OtdrMeasurements[0].Events. The
    earlier assumption that they were trace-only was wrong.
  - Auto now takes the newest result carrying events, whatever its type, so
    post-remedial work appears without re-analysing anything in FMS.

v0.2  (2026-08-14)   Raw trace reading
  - Decodes the OTDR sample blob and measures splice loss at a known distance

  - Distance axis calibrated from DataPoints.Resolution.

v0.1  (2026-08-14)   Loop legs
